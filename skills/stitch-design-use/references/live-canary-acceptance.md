# Stitch live canary acceptance

这份参考仅定义真实 Provider canary 的证据边界；它不包含凭据，也不把历史运行当作当前通过。

## 前置条件

- 使用目标发布版本安装后的插件，而不是源代码目录中的未发布实现。
- 凭据来自本地安全配置入口，日志不得输出 token、cookie 或认证头。
- 固定项目、屏幕、设备、画布尺寸与预期产物；记录插件版本和运行时间。

## 最小 smoke

1. 只读列出项目并读取一个已知屏幕。
2. 验证响应来自真实 Provider，且项目/屏幕标识与请求一致。
3. 下载一项允许的资产，验证文件存在、媒体类型、大小和哈希。
4. 若执行生成或编辑，先展示精确动作和付费/写入影响，获得当前轮次授权。
5. 写入后重新读取同一资源，确认远端状态和本地产物一致。

## Harness 验收

完整验收还必须保留以下独立证据：Stitch 原稿、导出资产、OCR/业务约束检查、roundtrip、可编辑性检查、视觉比较、显式人工审批和归档回执。

工作流手动触发成功或 Provider smoke 变绿，只能证明对应层级；它们不能代替人工批准，也不能证明所有 Harness 产物通过。

## 结果状态

- `PASS`：真实调用、产物和回读均通过，且证据绑定当前版本。
- `FAIL`：调用、产物或一致性检查失败。
- `SKIPPED`：可选检查未执行，必须说明原因。
- `BLOCKED`：缺少凭据、额度、授权或 Provider 可用性；不得伪造通过。

## 禁止事项

- 不把旧截图、缓存或其他版本的 receipt 当作当前证据。
- 不因超时自动重提交写操作；先按请求或资源标识查询。
- 不把视觉相似度替代可编辑性、业务正确性或人工审批。
