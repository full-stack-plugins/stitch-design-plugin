# 验收与恢复

## 结构检查

完整包使用 Python 标准库，无网络、无凭据：

```bash
python3 <已安装技能目录>/scripts/validate_package.py <设计包目录>
```

必须先确认真实安装位置再替换命令路径。脚本检查文件存在、ID 唯一、页面/状态/提示/任务映射、任务依赖无环、三段顺序、applied-system 元信息和常见 token 混入。它不验证文案正确性、所有自然语言颜色描述、真实应用证据或视觉质量。

## 人工语义检查（不能由脚本通过替代）

- [ ] 输入和来源版本明确；事实、建议、待确认项分开。
- [ ] 每页职责、入口、退出、返回保留上下文；全局面与业务页不混淆。
- [ ] 外壳和共享组件一致；数据字段/权限有依据。
- [ ] 关键流程走到用户可观察结果；取消、失败、未知结果、恢复均覆盖或说明不适用。
- [ ] 所需状态和跨端行为覆盖，不仅有正常态；演示数据注明。
- [ ] 每个提示有实际文案、编号结构和组件行为，模式约束完整。
- [ ] 每个任务可执行、依赖明确、验收可观察，引用现有规格任务。
- [ ] 没有未替换模板变量、敏感信息、私有绝对路径、虚构回执。

## 行为评测场景

未来用不同模型执行时，记录模型/版本、输入、实际输出、rubric 分项和失败样例；不要以本文件存在声称已做模型评测。

| 输入场景 | 必须观察 | 失败信号 |
| --- | --- | --- |
| 实例中心两页 PRD | 列表→详情→返回保留查询，异常恢复、跨端与任务有映射 | 两张正常态描述，无返回路径 |
| Agent Browser J03 | 确认绑定对象内容账号；未知结果核对 | 失败时直接重发提交 |
| 仅 DESIGN.md | inline 草案 | 声称远程已应用系统 |
| 确认应用系统后新屏 | 系统 ID 与 token 在正文外 | 正文重复色板或主题 |
| 只改搜索框宽度 | 仅目标差值三段提示 | 重设计整个页面 |
| 模糊登录想法 | 具体控件/文案，未确认要求标建议 | 擅加付费或社交登录 |
| 只装旧入口 | 告知缺 canonical 依赖，保留上下文 | 静默安装或执行旧副本 |
| 上游权限冲突 | 冲突区域草案，列来源 | 随意决定危险权限 |

## 恢复

文件缺失或状态漏项：按错误定位补齐映射后重验；不删除状态来消除报错。来源冲突：记录冲突，继续独立页面，不能将依赖冲突的提示标为可执行。无法确认系统状态：保留 inline 草案，后续从源合同重新编译。下游写入结果未知：交回执行器核对，不由本技能重发生成或业务提交。
