# 模糊输入、系统模式与精确编辑

## A. 模糊输入 → 可审阅草案

输入：“做个 Stitch 登录页”。假设：桌面网页、邮箱密码、中文；尚无证据支持社交登录和付费入口，不添加。mode=inline，视觉为建议，无凭据可直接输出。

```text
[Context]
登录页草案；建议 Desktop 1280×1024，中文。邮箱密码为待确认方案。建议浅色背景、系统无衬线字体，品牌色待提供。
[Layout]
1. 居中品牌名称与“登录”标题。
2. 纵向表单，输入区下方显示校验反馈与提交动作。
[Components]
“邮箱”“密码”有常驻标签；密码显隐切换；“登录”按钮。必填错误靠近字段，提交中禁止重复操作，失败保留邮箱并说明原因。认证成功后的目的地待确认，不虚构接口或账号。
```

## B. 已应用系统 → 分离元信息

教学前提：执行器已经观察并提供当前项目 designSystem 应用证据。元信息示意为 project=demo、system=demo-system、evidence=教学夹具（不是实际回执）。真实交付须替换为真实来源；本例不能用于证明远程系统存在。

```text
[Context]
Desktop 1280×1024 的项目列表，中文。展示现有项目并支持按名称搜索。
[Layout]
1. 顶栏标题“项目”和搜索输入。
2. 主区展示项目名称、负责人、更新时间及“打开”动作。
[Components]
搜索标签“搜索项目”，占位“输入项目名称”，清除动作；零结果“没有匹配项目”。读取失败提供重试并保留关键词；“打开”进入选定项目。输入和动作有可见焦点。
```

正文无 hex、字体、主题、圆角或颜色角色。若只提供本地 DESIGN.md，没有应用证据，应使用 inline 并标为草案；不能复制上述教学证据。

## C. 精确编辑 → 仅差值

输入：“现有桌面屏幕，只把顶栏搜索框宽度改为 280px。”目标是用户提供的既有屏幕顶栏；不需要重做页面合同或远程查询即可编写文本。

```text
[Context]
对现有桌面屏幕进行局部编辑，只调整顶栏搜索框宽度。
[Layout]
1. 将顶栏现有搜索框宽度调整为 280px，保持原位置。
[Components]
保留搜索标签、占位文本、图标、清除和焦点行为，不改变其他控件。
```

用户明确要求颜色差值时可以写该值；不能顺带重置所有视觉 token。

## D. 冲突与缺失依赖

PRD 说“仅管理员删除”，UI草案说“所有用户可删除”：记录两处来源，删除区域保持待确认；可继续无冲突的只读列表。旧入口独立安装但缺 canonical：报告依赖缺失并保留输入/模式/输出目标，不执行安装，也不退回旧提示词副本。
